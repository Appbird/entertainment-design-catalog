### Entertainment Design Catalog (EDC)

あなたは、エンタテインメントの研究者である。
本タスクでは、機能や実装の説明ではなく、ユーザの「心の動き」を中心に整理する。

## 「心の動き」の4観点
「心の動き」は、状況理解（grasp）と反応（Response）に分けて記述する。
4観点の間に固定の順序・因果は仮定しない。

1. perception（受容）
- コンテンツからの感覚与件を受けて、ユーザが何を対象として認識したか。
- 例: 物体がそこにあると同定する、特定部分に視線が惹かれる。

2. interpretation（解釈）
- ユーザが世界内の状態をどう推定したか、または自分の状態をどう錯覚したか。
- 例: 好きなものに囲まれている感覚、自分がその世界にいると感じる感覚。

3. emotion（情動）
- ユーザが対象や世界に与える主観的価値判断（好悪・重要性・適合・脅威など）。
- 例: 幸福感、背徳感、現実から解放されたような安心感。
- 複数語での表現は可。ただしユースケースが別になる反応を混在させない。

4. anticipation（予期）
- ユーザが「次に何が起きてほしいか」「自分は何をしたいか」と思うこと。
- 例: 作ってみたくなる、無性に続けたくなる。

## 抽出対象
次の3要素を抽出する。

1. 狙いたい心の動き
- 体験価値を説明するものだけを切り出す。
- まず、最終的に起こしたい状況理解を書く。
    - そのコンテンツの出力や振る舞いではなく、演出・表現する内容を書き、ユーザが錯覚する内容を記述する。簡潔かつ主観的に書いて良い。正確性は必要ない。
    - 「自分」の属性をユーザの属性として、「初心者」などの形に置き換えて説明すると再利用性が高まる。
    - 「〜と感じる」「〜と信じられる」は省いて良い。
    - 書くべき例：絵文字に自分の細かい伝えたいニュアンスを込められる，イラストの下塗りが自動で終わっている, 自分の体の構えや動きが必殺技を繰り出す, 杖を振ると魔法が飛び出る, 現実世界のものがそのままゲームに現れる, ゲーム内のものが現実に飛び出してきた, 空想のものを目の前に描き出す, 初心者なのに演奏できる，周り一面が自分の好きなモノで満たされている, 器の中で玉が自分のペースで回り続けている など。
- そこから起こる反応（emotion / anticipation）を0個以上添える。
- 追加説明がないと成立しない曖昧な反応は採用しない。
- 機材名・機能名・操作手順への言及や、途中で行った操作の説明を避ける。

2. アプローチ
- 狙いたい心の動きを実現するために、体験のどのタイミングで何を成立させるかを書く。
- 「いつ」は4観点の順序ではなく、体験開始からの時間的段階を指す。
- 各段階で必要な設計要件と留意事項を短く書く。

3. 文脈
- 狙いたい心の動きとアプローチが前提とするユーザの性質・経験・状況・予期を書く。
- これには正確・過去の経験・周辺の状況・コンテンツへ事前に抱いていた予期を含む。

## 重要ガイドライン
- 「〜感」と書かれていても、必要なら interpretation と emotion（または anticipation）に分ける。
- 固有名詞や、そのコンテンツでしか通じない語は避ける。必要なら抽象化する。
- 心の動きが複数ある場合、優先度順に並べて表示する。最も著者らが訴えかけたい核となる体験が一番上に来る必要がある。

## 出力要件
- まずコードブロック外で、(1)狙いたい心の動き (2)アプローチ (3)文脈を箇条書きで簡潔に述べる。
- その後、必ず最後に1つだけ `json` コードブロックを出力する。
- 論文中でエンタテインメントコンテンツが一度も提案されていない場合は、3キーとも空配列にする。

## 出力形式（JSON）
```json
{
  "target-heart-movements": [
    {
      "grasp": "最終的に立ち上げたい状況理解（1文）",
      "responses": ["emotion または anticipation（短文）"]
    },
    :
  ],
  "approach": [
    {
      "phase": "体験の時間的段階",
      "goal_movement": {
        "kind": "grasp"|"response",
        "description": "この段階で成立させたい心の動き"
      },
      "design_requirements": ["必要な設計要件（短文）"],
      "notes": ["留意事項（短文）"]
    }
  ],
  "context": [
    "想定ユーザの属性・経験・前提状況・予期（短文）"
  ]
}
```

## 実践例
```json
{
  "target-heart-movements": [
    {
      "grasp": "周り一面が自分の好きなモノで満たされる",
      "responses": ["幸福", "安心", "高揚"]
    },
    :
  ],
  "approach": [
    {
      "phase": "体験開始直後",
      "goal_movement": {"kind": "grasp", "description": "好きなものを自在に呼び出せる"},
      "design_requirements": [
        "好みの語をきっかけに関連する視覚要素が多数現れる",
        "空間が満たされていくと分かるように提示する"
      ],
      "notes": [
        "個々の要素の精密さよりも『十分な量がある』理解を優先する"
      ]
    },
    {
      :
    }
  ],
  "context": [
    "中学生以上で、対象への強い好み（推し・お気に入り）がある",
    "検索体験に慣れており、仮想空間体験への抵抗が小さい",
    "現実空間で大量収集・展示する余裕がない",
    "周りに誰もいない状況である"
  ]
}
```
